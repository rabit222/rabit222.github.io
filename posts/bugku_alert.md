思路：打开页面只弹了一个 alert 弹窗，点掉之后页面就没别的反应了，既没有输入框也没有链接。这种"页面一片空"的题，线索一般藏在响应内容或者请求头里。

问题：
1. 点掉弹窗后页面空白，不知道该点哪里。
2. 用查看源代码看了一遍，HTML 里没有明显提示，也没有注释。
3. 不知道题目想让我改什么。

解决：
1. 挂上 Burp 代理，刷新页面抓包，看完整的 HTTP 响应。弹窗内容其实是服务端返回的 JavaScript 里写的，提示信息也藏在响应体里。
2. 提示说要改 User-Agent。回到 Burp 的 Repeater，把请求头里的 User-Agent 换成题目要求的值，重新发送。
3. 响应里的内容变了，页面再刷新一次就弹出了 flag。提交通过。

补充：
1. 服务端为什么会用 User-Agent 判断身份？因为它省事——不用登录体系，一个字符串就区分了"谁在访问"。但请求头完全由客户端构造，所以这种判断等于没有判断。
2. 常被拿来做题的头还有：Referer（从哪跳来的）、X-Forwarded-For（真实 IP，反代后面常用）、Cookie（身份票据）、Accept-Language（语言/地区）、以及自定义的 X-开头头。
3. Burp 里改头的两种方式：Proxy 拦截时直接改，或者在 Repeater 里改完再发。后者更适合反复试不同值，因为不用每次重放整条流量。

工具：Burp Suite

踩坑记录：
1. 最先是在页面源码里找注释，什么都没有；又在 Console 里看有没有报错，也没有。
2. 试过直接用开发者工具的"网络条件"改 User-Agent 再刷新，但那条请求不是页面主文档发的，改了之后页面上还是没有变化。
3. 折腾了十几分钟才意识到：我应该看的是"页面加载时那一条请求的响应体"，而不是页面渲染出来的样子。
4. 用 Burp 的 Repeater 把改好头的请求重放之后，响应体里直接出现了 flag，这才是对的入口。

总结：页面"什么都不说"的时候，不要只盯着页面看，要去原始请求和响应里找。这题的关键知识点是 User-Agent 属于客户端可以随便伪造的请求头，服务端拿它当身份凭证本身就是错的。另外也算正式学会了 Burp 的基本流程：Proxy 抓包 → 右键 Send to Repeater → 改包 → 重放看响应。我还专门对比了"用开发者工具改请求头"和"用代理改请求头"的区别：前者对页面自己发起的请求不太可控，后者是所有流量的唯一出口，改起来最干净。
