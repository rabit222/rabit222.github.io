思路：Pikachu 的上传模块按防护强度分了三关：客户端检查（clientcheck）、服务端后缀检查（servercheck）、服务端内容检查（getimagesize）。防护越深，绕法越复杂。

问题：
1. 第一关改包就过了，第二关改包不行。
2. 不知道 getimagesize 到底检查什么。
3. 传上去的文件访问 404。

解决：
1. clientcheck：前端 JS 校验，抓包改文件名后缀为 .php 放行。
2. servercheck：服务端校验后缀白名单，改后缀不行，得换思路——传 .php5/.phtml 之类，或者配合 .htaccess。
3. getimagesize：服务端读文件头，构造图片头 + PHP 代码（GIF89a + <?php ... ?>）就能过。
4. 上传成功后访问文件，PHP 执行，提交通过。

补充：
1. 上传成功但访问 404，多半是路径不对或者上传目录被限制了。
2. 真实防御：白名单后缀 + 重命名 + 上传目录禁止脚本执行 + 独立域名。
3. getimagesize 只检查图片结构，不检查后面追加的内容，所以"图片马"一直好用。

工具：Burp Suite、十六进制编辑器

踩坑记录：
1. 第二关改后缀一直失败，后来才知道有白名单，得换可执行后缀。
2. 图片马加了 GIF89a 但还是 404，其实是上传目录不在 web 根下。
3. 上传成功没找到路径，看返回信息才定位到。

总结：上传题的核心是"防护在哪个环节"。前端、后缀、内容三层防护对应三种绕过，理解了分层就不会乱试。
