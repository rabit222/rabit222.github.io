title: 备份是个好习惯
date: 2026-10-06
tags: [Bugku, WEB, 源码泄露]
excerpt: 扫出站点备份文件，审计源码绕过判断拿 flag。
---

思路：题目名"备份是个好习惯"就是提示——站点上留了备份文件。和 source 那题是同一类（源码泄露），但这次不是版本控制目录，而是打包备份。

问题：
1. 不知道备份文件叫什么名字，盲猜了 index.php.bak、www.zip 都没中。
2. 用浏览器直接访问目录，返回 403，看不到文件列表。
3. 下载到压缩包之后，一开始只看首页逻辑，没找到 flag。

解决：
1. 用 dirsearch 挂常见备份后缀和常见备份名跑一遍（www.zip、web.zip、backup.zip、index.php.bak、wwwroot.rar 等）。扫出一个能下载的压缩包。
2. 下载解压，得到站点源码。这次重点不是首页，而是把所有 php 文件过一遍，找 include、eval、判断分支这类敏感点。
3. 源码里有一段逻辑：根据传入参数决定走哪个分支，构造合适的参数绕过判断后，页面就返回了 flag。提交通过。
4. 后来复盘时发现，其实不用全量扫，先看响应头里的 Server 和常见命名规则能省不少时间。

补充：
1. 备份文件的命名规律值得单独记：域名/项目名 + 后缀。后缀字典一般包含 zip、rar、tar.gz、7z、bak、old、swp、txt、sql。常见组合如 www.zip、web.zip、backup.zip、wwwroot.rar、index.php.bak、index.php~、.index.php.swp。
2. .sql 备份比源码更危险——里面直接是数据库结构和数据，往往是整站的账号密码。
3. dirsearch 提高效率的两个参数：-e 指定扩展名（收窄范围）、-t 调线程数（别太高，容易被封）。加 --exclude-text 可以过滤掉自定义 404 页面造成的误报。

工具：dirsearch

踩坑记录：
1. 手工猜了 index.php.bak、www.zip、backup.zip 几个常见名，都没中。
2. 第一次跑 dirsearch 用了默认配置，扫得特别慢，后来把扩展名收窄到 zip/rar/bak/tar.gz 才快起来。
3. 下载下来的压缩包一开始只看了首页源码，没找到东西，差点以为下错了文件。
4. 把包里的 php 文件全部过了一遍才定位到那段判断逻辑，教训是审源码不能只看入口文件。

总结：备份文件泄露的两个关键动作是"猜名字"和"审逻辑"。猜名字靠字典，审逻辑靠耐心。和 source 那题合起来，我现在遇到"页面没功能"的 Web 题会连着试三类东西：版本控制目录、备份文件、源码文件后缀。另外也学到了 403 不代表没有文件，只是不允许列目录，直接猜文件名照样能下。还有一个经验：备份文件经常放在子目录里（比如 /backup/、/www/），扫的时候别只扫根目录。
