---
title: 文件上传-前端验证
date: 2026-11-18
tags: [CTFHub, WEB, 文件上传]
excerpt: 只在前端 JS 里校验后缀，改包或者删掉校验逻辑就绕过去了。
---

思路：上传点只在前端用 JS 检查文件后缀，服务器端什么都不查。这种防护等于没有，绕过只需要让请求到达服务器时不带"合法后缀"。

问题：
1. 选 php 文件时浏览器直接弹"只能上传 jpg/png"，连上传都点不了。
2. 一开始想改文件后缀，但改成 .jpg 之后服务器又不会执行。
3. 不清楚 JS 校验到底在哪个环节拦的。

解决：
1. 打开 F12 看上传表单的 JS，找到校验后缀的那段代码，确认只是前端判断。
2. 绕过方式一：F12 删掉校验事件监听，或者直接把 input 的 accept 属性改掉。
3. 绕过方式二：先正常上传一个 jpg，用 Burp 把请求截下来，改文件名和后缀为 .php 再放行。
4. 上传成功，访问返回路径，PHP 执行，提交通过。

补充：
1. 前端校验永远不可信：请求可以完全绕过浏览器手工构造，服务器端不校验就等于没校验。
2. 同理，前端做的"禁止右键""禁止调试"这类限制，都只是防君子不防小人。
3. 正确的做法是服务端校验后缀白名单 + 重命名 + 上传目录禁止脚本执行。

工具：Burp Suite、浏览器 F12

踩坑记录：
1. 一开始只想到改后缀，结果改完不执行，白绕一圈。
2. 删 JS 监听之后浏览器还是拦，因为 HTML 的 accept 属性还在，得一起改。
3. 改包时忘了同步 Content-Type，服务器虽然不校验，但有的中间件会看，导致上传失败。

总结：前端校验是"用户体验"不是"安全措施"。做题时看到 JS 报错，第一反应应该是"这段逻辑在服务器上有没有副本"，答案通常是没有。
