思路：给的 pcap 里是数据库通信流量，MySQL 协议是明文的，追踪 TCP 流就能看到客户端发了什么 SQL、服务端返回了什么。

问题：
1. 一堆 TCP 包，看不出哪条是数据库流量。
2. 过滤条件不会写。
3. 看懂了 SQL 但不知道 flag 在哪。

解决：
1. 用 Wireshark 打开，先看统计——协议分层里有 mysql 就说明是数据库流量。
2. 过滤条件：mysql 或者 tcp.port==3306，只留下相关包。
3. 右键某条包 → 追踪 TCP 流，SQL 语句和结果集都在里面。
4. 找到包含目标数据的查询结果，提交通过。

补充：
1. MySQL 协议默认 3306，非默认端口要先从包内容里认出来。
2. 如果协议解析不出来，用"追踪 TCP 流"照样能读明文。
3. 同类思路也适用于 Redis、MongoDB、PostgreSQL 的明文流量。

工具：Wireshark

踩坑记录：
1. 一开始用 http 过滤，当然是空的，没意识到过滤错协议。
2. 追踪流出的是乱码，因为混了握手包，得从第一条数据包开始追。
3. 结果集里有大量无用行，翻了好几屏才找到目标。

总结：数据库类流量题的套路是固定的：识别协议 → 过滤 → 追踪流 → 找查询结果。理解协议是明文这一点，比会几个过滤器更重要。
