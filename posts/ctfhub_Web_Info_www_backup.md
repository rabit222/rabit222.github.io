title: 信息泄露-网站源码备份
date: 2026-11-18
tags: [CTFHub, WEB, 信息泄露]
excerpt: 打包上传时忘了删备份文件，www.zip 就在根目录躺着。
---

思路：很多站点部署时会把源码打包成一个压缩包放在 web 目录里，忘记删除。用备份文件名去撞，撞到就直接下载整站源码。

问题：
1. 不知道备份文件叫什么名字。
2. 目录扫描扫不到，因为不是随机名字而是固定套路。
3. 下载下来也不会拆。

解决：
1. 用常见备份名去试：www.zip、web.zip、wwwroot.zip、backup.zip、www.tar.gz、站点域名.zip。
2. 撞到之后下载，解压看源码，搜索 flag 关键字。
3. 没撞到就上目录扫描工具跑字典，找可疑的压缩包。
4. 提交通过。

补充：
1. 常见备份命名：www / web / wwwroot / backup / bak / 站点名 / 日期后缀。
2. 其他泄露源：.git、.svn、.DS_Store、IDE 配置目录、编辑器临时文件（xxx.php.swp）。
3. 防御：部署时不要上传源码包，web 根目录不放任何压缩包和版本控制目录。

工具：浏览器、dirsearch、7-Zip

踩坑记录：
1. 一开始只扫目录，扫不到就没思路了，其实要撞文件名。
2. 下载下来的压缩包有密码？没有，是我想多了，直接解压就行。
3. 解压出来目录特别深，找 flag 用了全局搜索。

总结：备份文件泄露是"低级但高发"的漏洞。这题让我学会了固定思路：先试备份名，再试版本控制目录，最后跑字典。
