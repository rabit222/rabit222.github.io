思路：打开题目是一个网页计算器，页面上给一道算术题（类似"请输入 12+34 的结果"），下面一个输入框和一个提交按钮。第一反应是前端题目，那校验逻辑大概率也在前端。

问题：
1. 老老实实把答案算对填进去，弹窗却说"答案错误"，试了好几次都一样。
2. 以为是自己算错了，重复算了几遍，确认没算错。
3. 刷新页面想换一道题，结果题目不变，一直是同一道。

解决：
1. 按 F12 打开开发者工具，切到 Sources / Network 看这个页面加载了什么。发现判断答案对错的逻辑是 JavaScript 写死的，和页面上显示的那道题不是一套东西——也就是说前端自己算出了一个结果拿去比对。
2. 既然校验在前端，那就有两种思路：一是直接绕过，二是伪造。我选的是后者：在开发者工具里找到校验函数，看它到底在比什么。
3. 按评论区提示，直接改响应内容，把服务端返回的提示改成页面期望的正确结果，再点提交，页面就吐出了 flag。
4. 提交通过。

补充：
1. 前端验证的常见形态有三种：一是 JS 里写死答案直接比对；二是算完把结果放进隐藏字段一起提交；三是用 disabled/readonly 之类属性限制你输入。三种都能绕过，思路各不相同（改 JS、改隐藏字段、删属性）。
2. 开发者工具里"改响应"有两条路：Network 面板对某条请求 Edit and Resend，或者装个代理（Burp）在响应回来的路上改。前者方便，后者更接近真实攻击。
3. 记住一个判断标准：如果断网或者刷新之后答案立刻变了，说明判断在服务端；如果答案永远只跟当前页面有关，判断就在前端。

工具：浏览器 F12 开发者工具

踩坑记录：
1. 第一反应是在开发者工具里改 DOM，把页面上显示的"错误"文字直接改成"正确"，结果提交之后依然失败——因为页面发请求时服务端返回的还是错的那份。
2. 试过在 Elements 面板把输入框的 maxlength 之类属性删掉，没有用，问题不在输入限制上。
3. 真正的关键点是"改响应"而不是"改页面"：浏览器看到的东西和服务端返回的东西是两回事，得让服务端那份变成对的。
4. 在 Network 面板对着那条提交请求点右键选 Edit and Resend，把响应里的判断结果改掉再发，这一步走通之后就很顺了。

总结：这题教的是"前端能看到的校验都不算校验"。凡是验证类的 Web 题，第一件事是看 JavaScript 里怎么判的，第二件事是想能不能直接改响应——因为这题真正的判断就发生在浏览器里，服务端根本没参与。另外也顺手熟悉了开发者工具的 Sources 面板怎么打断点、怎么改内存里的变量值。区分清楚 DOM、Network 里的请求、Developer Tools 里改的东西分别影响哪一层，是这题最大的收获。
