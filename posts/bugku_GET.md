思路：这是最基础的传参题，页面明确写着"请用 GET 方式提交一个名为 what、值为 flag 的参数"。属于 Web 的第一课。

问题：
1. 一开始只会在页面上找按钮点，页面上其实没有提交按钮，就卡住了。
2. 不知道参数该放哪里，试着在输入框里填了 flag，没反应。
3. 对"参数"这个概念没概念。

解决：
1. 看懂提示之后明白：GET 请求的参数是拼在 URL 后面的，格式是 ?键=值。于是直接在地址栏把 URL 改成 http://xxx/?what=flag 回车。
2. 页面立刻返回了结果，拿到 flag。提交通过。
3. 顺手挂 Burp 看了一眼这个请求的原始样子，确认请求行就是 GET /?what=flag HTTP/1.1，参数确实在 URL 里。

补充：
1. URL 的结构：协议://主机:端口/路径?参数1=值1&参数2=值2#锚点。锚点（#后面的部分）不会发给服务器，这点在做题时容易踩坑。
2. URL 里的中文和特殊字符要被"URL 编码"，比如空格变成 %20、& 变成 %26。有时候题目要求你传的值里本身就含 & 或 =，这时就得编码，否则会被当成参数分隔符。
3. GET 请求还有长度限制（受浏览器和服务器限制，一般几 KB），这也是为什么传文件、传长文本必须用 POST。

工具：浏览器地址栏、Burp Suite

踩坑记录：
1. 卡在"没有提交按钮"上很久，一直在页面上找可以点的地方。
2. 试过在页面输入框里输入 flag 再回车，由于没有表单提交逻辑，什么都没发生。
3. 手打 URL 的时候把参数名拼错了（写成 ?flags=flag），返回的还是提示页，检查了一遍才发现是键名写错。
4. 拼对之后一下就出来了，回头看这题简单得离谱，但当时确实卡了十几分钟。

总结：GET 传参是 Web 最基础的知识点：参数跟在 URL 后面，? 开始、& 分隔多个参数。这题虽然简单，但它把"请求"这个概念具象化了——以前在地址栏敲网址从来没想过那其实是一个请求。后面做 POST 那题时对比着看，一次就把 GET/POST 的区别记住了。另外也踩了个很有代表性的坑：参数名（键）和参数值都要和题目要求完全一致，大小写错了服务端就当没收到。
