思路：进页面之后页面疯狂刷新，根本来不及看清任何内容，像是一直在重定向或者刷新自己。题目名"你必须要让他停下"其实就是提示：想办法让它停下来。

问题：
1. 页面刷新太快，肉眼完全看不清内容。
2. 一开始以为是重定向死循环，去看 Network 面板，发现是一条条不停发出的请求。
3. 尝试按 ESC 停止加载，页面直接变成一片空白，还是没拿到东西。

解决：
1. 先试了禁用 JavaScript，结果页面干脆什么都不渲染了，说明内容不是靠 JS 生成的。
2. 改用 Burp 开拦截（Proxy → Intercept is on），让每一个请求都被卡住不往下走。这样页面就"停"住了。
3. 一个个放行请求，同时在响应里找线索。在某一个请求的响应体里直接看到了 flag。
4. 提交通过。

补充：
1. "页面自己动"分两类：一类是 HTTP 层面的（响应头 Location 配 302/301，或者 Refresh 头），一类是 JavaScript 层面的（location.href、setTimeout 刷新）。禁用 JS 只能拦住后者，这题就是前者，所以禁用 JS 没用。
2. 拦请求的工具不止 Burp，浏览器开发者工具里的 Network 面板勾上"慢速网络"也能把过程看清，但看不了原始字节，改包也不方便。
3. 遇到刷屏页面还有个土办法：直接看源码（view-source:）或者用 curl 请求一次，因为 curl 不会执行跳转和脚本。

工具：Burp Suite

踩坑记录：
1. 一开始按 ESC 想停止加载，页面确实停了，但只剩一片空白，什么内容都没有。
2. 禁用 JavaScript 之后页面干脆什么都不渲染，说明这个跳转/刷新不是靠 JS 做的，而是 HTTP 层面的重定向或者响应头里的刷新。
3. 试过在开发者工具里勾 Disable cache 再刷新，没用，问题不在缓存。
4. 最后是靠 Burp 开拦截把每个请求卡住逐个放行才看清——这也让我第一次直观理解到"拦截代理"和"看历史记录"的区别。

总结：题目名本身就是解题提示。这题的思路是"与其让浏览器渲染出来给我看，不如把请求拦住直接看原始响应"。也顺带理解了拦截代理和浏览器开发者工具的区别：开发者工具是"看已经发生的事"，代理是"让事情发生得慢一点"。以后再遇到刷屏、闪一下就跳走的页面，第一反应就是开拦截。顺带记住两个关键词：HTTP 状态码 302 重定向，以及响应头里的 Refresh，这两者是"页面自己动"的常见原因，跟 JavaScript 跳转要分开对待。
