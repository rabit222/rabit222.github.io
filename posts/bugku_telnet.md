思路：题目给了一个地址和端口，说这是一个 telnet 服务，让我们连上去找 flag。属于服务类题目，考的是会不会用工具。

问题：
1. Windows 默认没装 telnet 客户端，敲 telnet 命令提示找不到。
2. 装好之后连上去，黑窗口里就一个提示符，不知道该干什么。
3. 不知道这个环境里 flag 放在哪。

解决：
1. 在"控制面板 → 程序和功能 → 启用或关闭 Windows 功能"里勾上 Telnet 客户端；懒得装的话用 nc 或者 PuTTY 选 Telnet 模式也一样。
2. 连上去之后先把环境摸一遍：先 ls 看当前目录，再 cd 到上级目录，把常见位置（当前目录、/root、/home、/tmp）都翻一遍。
3. flag 就放在其中一个目录里，cat 出来即可。提交通过。
4. 顺手试了 whoami、uname -a，看看自己是什么权限、什么系统，养成习惯。

补充：
1. telnet 是最早的远程登录协议之一，明文传输（包括密码），现在只在内网设备调试或者 CTF 靶机里见得到，实际运维都用 ssh。
2. 连上陌生 Linux 环境的习惯动作：whoami 看身份、pwd 和 ls 看位置、cd .. 往上翻、cat /etc/passwd 看用户、find / -name "*flag*" 全局找。找文件时 find 比一个个目录翻快得多。
3. Windows 上替代方案：nc（netcat）直接 nc 主机 端口，或者用 Python 的 socket 写两行代码也能连，PuTTY 选 Raw/Telnet 模式也行。

工具：telnet、nc、PuTTY

踩坑记录：
1. 第一反应是在浏览器里直接访问那个地址，浏览器不认 telnet 协议，只弹了个报错。
2. 装完客户端连上去之后，敲 ls 没有任何输出，以为命令不对，其实是当前目录本来就是空的。
3. 在空目录里卡了一会儿，后来才想到应该 cd .. 往上翻。
4. 也试过直接 cat flag，路径不对报错，还是老老实实先列目录再找文件。

总结：这类"给你一个服务让你连"的题，难度不在技术而在工具和习惯。收获有两个：一是 Windows 上怎么补 telnet 客户端；二是连上陌生环境后的固定动作——先看自己是谁、在哪，再翻目录。另外也理解了 telnet 是明文协议，现在实际运维基本用 ssh 代替它。顺带记住一条 Linux 常识：ls 没输出不等于命令失败，很可能只是目录里真的什么都没有，此时应该换目录而不是怀疑命令。
