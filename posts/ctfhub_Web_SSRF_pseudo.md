---
title: SSRF-伪协议读取文件
date: 2026-11-18
tags: [CTFHub, WEB, SSRF]
excerpt: 用 file:// 让服务器读本地文件，gopher/dict 还能打内网服务。
---

思路：SSRF 不只支持 http，服务器用的请求库一般支持多种协议。file:// 可以直接读本地文件，不用访问任何网络。

问题：
1. 只试过 http://，不知道还能用别的协议。
2. 不确定 file:// 会不会被过滤。
3. 读文件时路径怎么给。

解决：
1. 提交 file:///etc/passwd，页面直接返回文件内容，说明协议可用、没有白名单限制。
2. 用同样的方式读目标文件，或读站点源码找进一步信息。
3. 后续可尝试 dict://、gopher:// 打内网服务。
4. 提交通过。

补充：
1. 常用协议：file://（读文件）、dict://（探测服务）、gopher://（构造任意 TCP 数据，打 Redis 等）。
2. gopher 是最强的：可以精确控制发出去的字节流，相当于手工构造任意协议报文。
3. 防御：只允许 http/https、禁止跳转、统一出口代理并校验目标地址。

工具：Burp Suite

踩坑记录：
1. 一开始不知道还有别的协议，只会在 http 上打转。
2. file:// 后面斜杠数量写错（file:///etc/passwd 是三个斜杠），少一个就读不到。
3. 想用 gopher 打 Redis，但返回包看不到，因为 SSRF 不回显，得用盲打思路。

总结：SSRF 的能力边界由"请求库支持哪些协议"决定。file:// 是最容易验证的一个，gopher:// 是威力最大的一个。
