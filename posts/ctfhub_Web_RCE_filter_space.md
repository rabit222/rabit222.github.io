思路：这题把空格拉黑了，但 shell 里命令和参数的分隔方式不止空格一种。

问题：
1. 命令里带空格就被拦，直接报错或者不执行。
2. 知道 IFS 这个技巧但不清楚写法。
3. 试了 %20 没用，因为解码之后还是空格。

解决：
1. 用 $IFS 代替空格：cat$IFS/flag（IFS 在 shell 里默认就是空格、Tab、换行的集合）。
2. 用 Tab：cat%09/flag，URL 里写 %09。
3. 用重定向符当分隔：cat</flag 也能工作。
4. 读到内容，提交通过。

补充：
1. IFS 的几种写法：$IFS、${IFS}、$IFS$9（$9 是空参数，用来分隔多个空格）。
2. < 和 > 重定向符不需要空格就能分隔命令和参数：cat<flag。
3. 花括号扩展也能造空格：{cat,/flag}，展开后变成两条命令。

工具：Burp Suite

踩坑记录：
1. 一开始写了 IFS 但没加引号保护，本地测试时被 shell 提前展开，和服务器上表现不一致。
2. 用 %09 时忘了 URL 编码，直接写 Tab 字符，请求被截断。
3. IFS 后面紧跟路径时会被当成一个词，得用引号或者 $9 分隔。

总结：空格过滤看起来很难绕，其实 shell 对空白的定义很宽（IFS 包含空格、Tab、换行）。这题教会我：理解 shell 的解析规则，比记 payload 更重要。
