title: 信息泄露-.DS_Store
date: 2026-11-18
tags: [CTFHub, WEB, 信息泄露]
excerpt: macOS 压缩目录时留下的 .DS_Store 会泄露目录里所有文件名。
---

思路：站点是从 macOS 打包上传的，目录里残留了 .DS_Store 文件。这个文件记录了该目录下所有文件名，直接访问就能看到源码列表。

问题：
1. 不知道 .DS_Store 是什么，也不认识这个文件名。
2. 访问之后是二进制内容，看不懂。
3. 不知道拿到文件名列表之后怎么继续。

解决：
1. 访问 http://目标/.DS_Store，下载下来。
2. 用工具解析（ds_store_exp 脚本或 strings 提取），得到目录内的文件名列表。
3. 按文件名直接访问源码、备份、配置文件，找到包含 flag 的那个。
4. 提交通过。

补充：
1. .DS_Store 是 macOS Finder 自动生成的目录索引，记录图标位置和文件名，打包上传时经常被一起带上。
2. 同类残留文件：.git、.svn、.hg、.idea、.vscode、Thumbs.db（Windows）。
3. 防御：部署时排除隐藏文件，服务器不解析点开头的文件。

工具：浏览器、ds_store_exp、strings

踩坑记录：
1. 一开始不知道这是个"文件"，以为是目录，访问 404 就放弃了。
2. 下载下来用记事本打开是乱码，才想起来要解析。
3. 解析出的文件名里有几个是备份文件，直接访问就能看源码。

总结：这题说明"开发者的工具链也会泄露信息"。做完之后我养成了习惯：先看看站点根目录下有没有 .git、.DS_Store 这类残留。
