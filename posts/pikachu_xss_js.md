---
title: Pikachu-XSS(js输出)
date: 2026-11-23
tags: [Pikachu, WEB, XSS]
excerpt: 输入被拼进 script 里的变量，用引号或 </script> 截断。
---

思路：这一关的输入被动态写进 <script> 里的 JS 变量，比如 var x = "输入"。HTML 实体编码在这里没用（JS 不解析实体），需要闭合 JS 字符串或截断 script 标签。

问题：
1. 输入引号后被转义，闭合不了。
2. 不知道代码具体长什么样。
3. 实体编码后功能正常但 XSS 不成立。

解决：
1. 先看页面源码，找到输入在 script 里的位置和引号类型。
2. 如果是双引号包裹：输入 ";alert(1);// 闭合字符串并注释掉后面。
3. 如果引号被转义：用 </script> 提前结束脚本块，再注入 <img src=x onerror=alert(1)>。
4. 触发成功，提交通过。

补充：
1. JS 上下文的转义和 HTML 完全不同：HTML 实体在 JS 里就是普通文本。
2. 防御：不要动态拼接 JS 代码，用 JSON 序列化传数据；必须拼接时用 JS 专用转义。
3. 这题和"htmlspecialchars 那关"正好互补：一个错在少转义，一个错在转错了地方。

工具：浏览器、Burp Suite

踩坑记录：
1. 先用了 HTML 实体编码，结果 JS 里显示的是字面量，功能坏了 XSS 也没成。
2. 注释符 // 后面没换行，导致后面的代码被注释掉但语法报错。
3. </script> 截断后，剩下的部分被浏览器当成 HTML 解析，才想到加 img。

总结：XSS 的本质是"代码和数据混在一起"。同一个字符在不同上下文里的含义不同，转义方式也就不同——这是整道题最大的收获。
