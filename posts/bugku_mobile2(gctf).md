思路：附件是一个 apk 文件，属于安卓逆向。之前只做过 Windows 上的 exe 逆向，这是第一次碰安卓，先解决工具问题再谈分析。

问题：
1. 环境不熟，不知道用 jadx 还是 apktool，也不确定要不要装安卓模拟器。
2. jadx 命令行版本参数多，一开始跑出来的输出目录结构看不懂。
3. 反编译出来一堆 smali 和 Java 文件，不知道从哪看起。

解决：
1. 换成 jadx-gui（图形界面版），直接把 apk 拖进去，左侧是包结构，右侧是反编译出来的 Java 代码，比命令行友好得多。
2. 用全局搜索（Search）搜关键字：flag、key、password、success 这类字符串。安卓逆向里字符串是最快的入口，和 exe 逆向按 Shift+F12 找字符串是同一个思路。
3. 跟着搜到的字符串定位到对应的类和判断逻辑，顺着代码走一遍，就能得到需要的内容。提交通过。
4. 顺便用 apktool 反编译了一份，对照看 AndroidManifest.xml 和资源文件里的提示。

补充：
1. APK 就是个 zip：改后缀解压能看到 classes.dex（Java 字节码）、resources.arsc（资源索引）、AndroidManifest.xml（清单）、lib/（so 库）、assets/（原始资源）。用 apktool 能把这些还原成可读形式。
2. 两个工具的分工：jadx 直接反编译成 Java 代码，适合读逻辑；apktool 拆包成 smali 和资源，适合改包重打包。CTF 里如果只看不改，jadx-gui 就够了。
3. 安卓逆向的下一步进阶方向：动态调试（frida 挂钩子）、so 层逆向（IDA 分析 libxxx.so）、加固脱壳。这题只是入门，但"先搜字符串再读逻辑"这个顺序在所有这些场景里都一样管用。

工具：jadx-gui、apktool

踩坑记录：
1. 先下了 jadx 命令行版，参数太多没搞明白，输出目录里一堆 smali 看得头大。
2. 想过装安卓模拟器动态调试，但下载和配置成本太高，先放弃了。
3. 换 jadx-gui 之后顺手很多，但也犯了"一上来就读代码"的错，翻了半天没找到重点。
4. 改成先全局搜字符串（flag、key、password），两分钟就定位到了关键类。

总结：安卓逆向入门的两个动作是"反编译"和"全局搜字符串"，剩下的逻辑再慢慢看。这题和之前的 exe 逆向（入门逆向那题）思路是通的：先找字符串，再看谁引用它。区别只是工具链不同——Windows 用 IDA/DIE，安卓用 jadx/apktool。另外知道了 apk 本质就是个 zip 包，改后缀也能解开看里面的 dex 和资源。也第一次体会到"先搜后读"这个顺序的重要性：面对几万个反编译出来的文件，通读是不可能的，必须靠字符串定位缩小范围。
