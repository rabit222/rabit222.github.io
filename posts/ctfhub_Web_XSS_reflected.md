---
title: XSS-反射型
date: 2026-11-18
tags: [CTFHub, WEB, XSS]
excerpt: 参数被直接拼进 HTML 回显，构造 script 让它在受害者浏览器里执行。
---

思路：反射型 XSS 的输入会被原样输出到响应页面里，不落库，只在这次请求里生效。只要找到"输入的数据出现在输出里"的位置，就能注入脚本。

问题：
1. 不确定哪个参数会被回显。
2. 输入了标签发现被转义，不知道是被过滤了还是编码了。
3. 不知道最终执行的效果怎么验证。

解决：
1. 先做探测：在参数里输入一个独特的字符串，看它出现在响应的哪里，确认回显点。
2. 判断编码：输入 <b>test</b>，如果页面把它当标签渲染，说明没转义；如果显示成文本，说明做了 HTML 实体编码。
3. 找到不过滤的参数，构造 <script>alert(1)</script>，页面弹窗即成功。
4. 换成更稳的写法（<img src=x onerror=alert(1)>），确认后提交。

补充：
1. 反射型 XSS 需要诱导受害者点击带 payload 的链接，属于"一次性的"，危害在于钓鱼。
2. 常见绕过：过滤了 script 就换 img/onerror、svg/onload；过滤了括号就换模板字符串；过滤了 alert 就换 print/confirm。
3. 真正的验证方式是"在浏览器里执行了"，而不是"页面上出现了这段文字"。

工具：浏览器、Burp Suite（看原始响应，确认有没有被编码）

踩坑记录：
1. 第一次只看页面显示，没看 Burp 里的原始响应，把编码当成了过滤。
2. 直接复制别人 payload 里的引号风格，和这里的 HTML 上下文不匹配，一直不执行。
3. 忘了确认输出位置：payload 插在属性里和在标签体里，闭合方式完全不同。

总结：XSS 的第一步永远是"看上下文"——你的输入落在 HTML 的哪个位置：标签体、属性、script 块、注释。位置决定了闭合和构造方式，同一个 payload 换个位置就失效。
