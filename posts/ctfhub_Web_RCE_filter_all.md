title: 命令执行-综合过滤
date: 2026-11-18
tags: [CTFHub, WEB, RCE, 命令执行]
excerpt: 空格、关键字、连接符全被过滤，用 base64 编码整条命令绕过去。
---

思路：这题的过滤很狠，空格、cat、斜杠、分号基本都被拦。硬拼 payload 很难，换成"编码执行"的思路：把命令 base64 编码，用只含安全字符的方式解码后交给 shell。

问题：
1. 各种关键字都被拦，常规 payload 全灭。
2. 不知道还有哪些字符能用。
3. 编码之后不知道怎么让服务器解码执行。

解决：
1. 先探哪些字符可用：字母数字和 = 一般都在，这就是 base64 的空间。
2. 把目标命令 base64 编码，构造：echo 编码串|base64 -d|bash。
3. 关键点：这条命令里只需要字母、数字、等号和管道，不含被过滤的关键字和空格（用 IFS 或者干脆把空格写进编码里）。
4. 命令执行成功，拿到结果，提交通过。

补充：
1. 这是"绕过过滤"的通杀思路：只要能构造出"解码 + 执行"，被过滤的是原始命令，不是编码后的字符串。
2. 同类手法：hex 编码、xxd -r -p、printf 拼接。
3. 防御侧看，这种绕过说明基于字符黑名单的防护本质上是纸糊的。

工具：Burp Suite、本地 shell

踩坑记录：
1. 一开始编码了但忘了加解码管道，echo 直接把 base64 串打出来了。
2. base64 里的 = 号在 URL 里没问题，但 + 会被当成空格，得编码成 %2b。
3. 管道符也被过滤，改用 base64 -d<<< 或者用变量中转。

总结：综合过滤题最好的解法不是"逐个绕"，而是"整体换形式"——把被过滤的内容藏进编码里，让过滤器看不到关键词。
