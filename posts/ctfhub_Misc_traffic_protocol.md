思路：最常见的流量分析题，pcap 里是一堆 HTTP 请求。除了看请求内容，还可以用"导出对象"把传输过的文件一次性拉出来。

问题：
1. 请求太多，逐条看效率低。
2. 不知道文件藏在哪个请求里。
3. 导出的文件打不开。

解决：
1. 先过滤 http，看请求列表，重点关注 POST 上传和 GET 下载。
2. 用 File → Export Objects → HTTP，列出所有传输过的文件，逐个导出。
3. 打开导出的文件（图片、压缩包、文本），找线索。
4. 提交通过。

补充：
1. 同类的导出功能还支持 SMB、FTP、TFTP、IMF（邮件），不同协议各自导出。
2. 如果是加密的 HTTPS 流量，需要会话密钥（SSLKEYLOGFILE）才能解密。
3. 文件下载还可以用"追踪流 + 手动另存"，但导出对象更快。

工具：Wireshark

踩坑记录：
1. 一开始逐条请求看，看了几十条才想起有导出功能。
2. 导出的图片只有一半，因为传输被分片了，得看完整流。
3. 导出的压缩包有密码，又回到密码破解的流程。

总结：流量分析题的第一反应应该是"先导出，再过滤"。导出对象能一次性把传输的文件都列出来，比逐条翻快得多。
