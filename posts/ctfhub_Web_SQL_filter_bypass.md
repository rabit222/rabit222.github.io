---

思路：这题和普通注入一样，但后端加了黑名单：select、and、or、空格、union 这些词可能被过滤。思路从"写 payload"变成"在过滤规则下把等价的 SQL 重新表达出来"。

问题：
1. 一开始按常规 payload 打，页面直接报关键字错误，或者干脆返回"非法输入"。
2. 不知道过滤规则具体是什么，试一次失败一次，像在猜谜。
3. 知道有注释、大小写这些技巧，但不知道哪个能用。

解决：
1. 先探规则：依次只发单个关键字（select、union、and、空格、分号、单引号），观察哪一个触发拦截，把黑名单摸出来。
2. 针对被拦的关键字逐个替换：大小写混写、关键词中间插内联注释 /*!50000select*/、用 + 或 %09 代替空格、用 && 代替 and、|| 代替 or。
3. 用等价表达绕过 select 被拦：用堆叠或者报错函数直接取数，不一定要走 UNION。
4. 组合出完整 payload，页面回显数据，提交通过。

补充：
1. 内联注释 /*!...*/ 是 MySQL 特有的，注释里的内容会被执行，是绕关键字过滤的经典手段。
2. 大小写绕过依赖后端过滤是区分大小写的字符串匹配，很多简单 WAF 都栽在这里。
3. 空格被过滤时的替代：/**/、%09（Tab）、%0a（换行）、括号（select(1)）。
4. 过滤规则和数据库版本强相关，绕不过去时先确认能不能用等价函数，别硬刚。

工具：Burp Suite、sqlmap（--tamper 脚本就是干这个的）

踩坑记录：
1. 没有系统探规则，一直在随机试 payload，效率极低。
2. 用内联注释的时候版本号写错（/*!50999*/ 这类），注释没被执行，白白浪费几轮。
3. 换行符在 URL 里要编码成 %0a，直接写换行是无效的。

总结：绕过不是"背 payload"，而是"先确定黑名单，再找等价表达"。任何一条 SQL 都有很多种写法，过滤做得越粗，等价空间越大。这也解释了为什么黑名单方案本质上不可靠。
