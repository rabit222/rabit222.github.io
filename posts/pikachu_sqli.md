思路：Pikachu 的 SQL 注入模块按"输入位置"分了四类：数字型（id 直接拼）、字符型（单引号包裹）、搜索型（LIKE 拼接）、xx 型（引号加括号）。每种的闭合方式不同，但后面取数据的思路是一致的。

问题：
1. 四道题看起来一样，不知道区别在哪。
2. 字符型怎么都闭合不上。
3. 搜索型不知道 % 号怎么处理。

解决：
1. 数字型：id=1 and 1=1 / and 1=2 对比响应，确认注入点，然后 union 取数据。
2. 字符型：先试 id=1'，报错说明单引号被拼进去了，用 1' and '1'='1 闭合。
3. 搜索型：找到输入落在 LIKE '%xxx%' 里的位置，用 %' and '1'='1 闭合。
4. xx 型：输入落在 ( '$x' ) 这种结构里，用 ') 闭合。
5. 拿到 admin 的账号密码，提交通过。

补充：
1. 判断类型的三板斧：单引号报错、and 1=1/1=2 对比、order by 数出列数。
2. Pikachu 数据库里默认有 users 表，字段是 username/password/id，直接 union 就能读。
3. 防御：参数化查询，字符型和数字型都不用手工转义。

工具：浏览器、Burp Suite

踩坑记录：
1. 一上来就 union，没先判断闭合方式，语法错误一堆。
2. 搜索型的 % 没处理好，把闭合符当成了模糊匹配的一部分。
3. union 的列数猜错，试了好几次才数对。

总结：注入的第一步永远是"确定输入落在 SQL 的什么位置"。闭合方式对了，后面所有技巧都是通用的。
