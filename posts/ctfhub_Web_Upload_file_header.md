date: 2026-11-18

excerpt: 服务器读前几个字节判断类型，加个 GIF89a 前缀就能骗过去。
---

思路：这题会读取文件开头若干字节，检查是不是合法图片。只要在 PHP 代码前面加一个图片文件头，既能通过检查，也不影响 PHP 解析。

问题：
1. 传 php 提示"文件内容不是图片"。
2. 不知道它检查的是哪几个字节。
3. 担心加了前缀之后 PHP 不执行。

解决：
1. 上传一个真的 gif，观察它接受；再上传内容为空的 php，观察它拒绝，确认是内容检查。
2. 构造文件：开头写 GIF89a，后面接 PHP 代码。GIF 的文件头只有 6 字节，不影响后面代码。
3. 上传成功，访问执行，提交通过。

补充：
1. 常见文件头：GIF89a、\xff\xd8\xff（JPEG）、\x89PNG（PNG）。
2. PHP 解析时会把 <?php ... ?> 之外的内容当普通文本输出，所以前缀不会影响执行。
3. 如果服务端用 getimagesize 这类函数二次校验，只加文件头可能不够，还得补上完整的图片结构。

工具：Burp Suite、十六进制编辑器

踩坑记录：
1. 直接把 "GIF89a" 当文本写进文件，编码问题导致字节不对。
2. 加了头之后 PHP 还是没执行，其实是上传目录不允许执行，跟文件头无关。
3. 有的检测会读宽高，只有 6 字节头不够，得用一张真的小图拼。

总结：文件头检查防的是"随手改名"，防不住"精心构造"。安全上的正确做法是不信任文件内容做类型判断，或者干脆把上传目录放到 web 根之外。
