思路：打开题目页面只有一句话，大意是"这里什么都没有，去别处找找"。Web 题里页面越干净，越说明东西在源码或者备份文件里。

问题：
1. 页面没有功能点，查看源代码也没有注释提示。
2. 不知道源码该从哪里拿。
3. 对 Git 的目录结构不熟，一开始不知道 .git 目录暴露意味着什么。

解决：
1. 按常规套路先在 URL 后面试常见泄露路径：/.git/ 能访问、/.svn/ 也能访问，说明源码目录直接暴露在网站上。
2. 用 GitHack 把 .git 扒下来还原源码（也可以手撸 wget -r 拉 .git 再 git reset --hard）。svn 泄露同理，用 dvcs-ripper 之类的工具。
3. 用 dirsearch 扫了一遍目录，确认还有没有别的可疑文件。
4. 在还原出来的源码里翻到关键判断逻辑，跟着逻辑构造请求，拿到 flag。提交通过。

补充：
1. .git 泄露能还原源码的原理：Git 会把所有历史对象放在 .git/objects 下，只要有这个目录就能重建整个仓库（包括你删掉的旧版本）。所以一旦 .git 被暴露，等于源码和历史提交全泄露，有时 flag 就藏在已经被删掉的那次提交里——那种情况要用 git log 把历史翻出来。
2. 类似风险：.svn/.hg/.bzr、.DS_Store（macOS 遗留，会泄露目录结构）、web.config、.env（配置和密钥）、以及编辑器留下的 .swp 临时文件。
3. 判断依据很简单：直接访问站点根目录加这些名字，能下就是暴露了。

工具：GitHack、dirsearch

踩坑记录：
1. 先在页面源码和 Elements 里翻了一遍，没有注释也没有隐藏元素。
2. 试过直接访问 /.git/config，返回 404，以为这条路不通；换成 /.git/HEAD 才看到内容，说明目录确实暴露了。
3. 想手动 wget -r 把 .git 拉下来，文件太多而且顺序容易乱，最后还是用了 GitHack。
4. dirsearch 扫出来一堆 200 的路径，一开始全看了一遍浪费不少时间，后来只挑可疑的看。

总结：.git / .svn / .hg 泄露是 Web 题的高频考点，原理是部署时把版本控制目录一起传上了服务器，攻击者可以据此还原出完整源码。学到两点：一是遇到"什么都没有"的页面先试这些路径；二是拿到源码之后重点是审逻辑，flag 通常在源码里的某个判断分支上，而不是明文写着。另外也第一次理解了"泄露"为什么危险：源码里往往有数据库口令、密钥、注释掉的调试接口，泄露的代价远不止一道题的 flag。
