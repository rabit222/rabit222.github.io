title: SQL注入-堆叠注入
date: 2026-11-18
tags: [CTFHub, WEB, SQL注入, 堆叠注入]
excerpt: 分号后面再写一条语句，用它来 INSERT/UPDATE，甚至写文件。
---

思路：普通注入只能在原 SQL 后面追加条件，堆叠注入可以在分号后接一条独立语句。这意味着不只能读，还能写——改数据、插数据，配合配置还能读写文件。

问题：
1. 不确定后端是不是支持多语句执行。
2. 试了好几条语句都没生效，不知道是语法问题还是驱动不支持。
3. 不清楚堆叠注入和普通注入的使用边界，什么时候该用哪种。

解决：
1. 先测支持性：id=1;select 1 这类请求，看返回有没有异常或多条结果，确认批量执行是否开启。
2. 确认之后写库：用 INSERT 往表里插一条自己可控的数据，再通过页面正常查询验证写入成功。
3. 再试改：用 UPDATE 把某个字段改成已知值，回到页面看变化，确认写权限存在。
4. 最后读回最终目标数据，拿到结果后提交通过。

补充：
1. 堆叠注入能不能用，取决于数据库驱动：PHP 的 mysqli 支持多语句（mysqli_multi_query），PDO 默认也支持部分场景，所以老环境经常能打。
2. 堆叠语句里不能用 UNION 那种"拼接结果集"的思路，因为每条语句的结果是独立的，页面一般只显示第一条的结果。
3. 能用堆叠的时候，读写文件（INTO OUTFILE）和改数据是最有价值的方向，比读数据危害更大。

工具：Burp Suite、sqlmap（--technique=S）

踩坑记录：
1. 第一条语句忘了加分号，直接语法错误。
2. 插入数据后没去页面验证，以为失败，其实插进去了，重复插了三条。
3. 碰到过一次环境里 multi_query 被关掉，堆叠完全无效，当时以为是 payload 写错，查了半天文档。

总结：堆叠注入的价值在于"突破只读"，从查询变成执行。判断能不能用只需要一条试探语句，成本很低，值得在每次注入时顺手试一下。
